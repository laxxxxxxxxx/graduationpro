### 账号1：student001（张三·计算机大三）— 学业压力精准匹配

**账号画像**：
```
测评：SDS轻度抑郁(45分)
画像：stress=medium, anxiety=medium, depression=low
主导问题：学业压力,考试焦虑
标签：压力管理(85), 学习效率(78), 考试焦虑(72)
行为：考试焦虑(浏览+点赞), 时间管理(浏览+完成), 情绪管理(浏览)
```

**推荐预期**：
- 排名靠前：时间管理与学习效率、如何应对考试焦虑
- reasons："与您兴趣相似的用户也喜欢"、"符合您的兴趣标签"、"根据测评结果推荐"
- 算法特征：Content-Based的"学业压力"标签 + Profile-Based的"考试焦虑"关键词双重命中

**答辩讲解要点**：
> "张三的 dominant_issues 是'学业压力,考试焦虑'。Profile-Based 规则4检测到'学业'关键词 → 时间管理、学习效率、考试焦虑类资源得分75。同时 Content-Based 的兴趣标签'学习效率(78)'、'考试焦虑(72)'与资源关键词做内积匹配。User-CF 和 Item-CF 也基于他的浏览行为提供协同信号。四路算法从不同方向汇聚到同一个结论——张三需要学业压力相关资源。"

**覆盖场景**：Profile-Based 规则4（学业问题精准匹配）、Content-Based 标签匹配、四路混合融合

### 操作演示1：student008（郑十·艺术大三）— 冷启动→测评→推荐从无到有

**初始状态**：纯冷启动（无测评/无行为/无画像/无标签）  
**演示目标**：展示"做心理测评 → 生成心理画像 → Profile-Based推荐激活"的完整链路

#### 操作步骤：

**Step 1：展示冷启动状态**
```
1. 登录 student008
2. 进入"个性化推荐"页面
3. 观察推荐列表：应该全是热门资源（algorithm_type=hot）
   - 排序按 view_count 降序（恋爱心理学680 > 抑郁识别520 > 情绪管理410...）
   - 所有资源的 finalScore 相近（均为兜底分数）
```
> **讲解**："郑十刚注册，没有任何数据。四路算法全部空转，系统触发冷启动兜底——按浏览量返回全站热门资源。"

**Step 2：做SDS抑郁自评量表**
```
1. 进入"心理测评" → 选择"SDS抑郁自评量表"
2. 答题策略：选择偏向"中度抑郁"的选项
   - 情绪低落、失眠、食欲减退、自我评价低等方向的选项
   - 目标：让测评结果落在 53-62 分区间（轻度~中度抑郁）
3. 提交测评 → 查看测评报告
```
> **讲解**："现在郑十完成了SDS量表，系统在后台做了三件事：① 写入 user_assessment 测评记录；② 生成 user_psychological_profile 心理画像（depression=medium）；③ 自动写入 user_interest_tags 兴趣标签（'抑郁调适'、'情绪管理'等）。"

**Step 3：查看推荐变化**
```
1. 返回"个性化推荐"页面（下拉刷新）
2. 观察推荐列表变化：
   - 抑郁症相关资源应该出现（抑郁情绪的识别与应对、积极心理学实践）
   - algorithm_type 变为 profile_based + content_based（不再是hot）
   - reasons 出现"根据您的测评结果推荐"
```
> **讲解**："做完测评后，Profile-Based 立即激活。depression=medium 触发规则3 → 推荐抑郁干预/自我关怀类资源得分70。dominant_issues 中的关键词与资源关键词精确匹配 → 得分80。测评自动写入的兴趣标签'抑郁调适(85)'驱动 Content-Based。推荐结果从'热门堆砌'变成'对症下药'——这就是心理画像作为冷启动引擎的核心价值。"

**覆盖场景**：冷启动→测评→画像生成→Profile-Based激活、热门兜底→精准推荐的转变过程

### 操作演示2：student007（吴九·数学大二）— 写日记→刷新标签→推荐变化

**初始状态**：有浏览行为(4条)但无测评/无画像/无兴趣标签  
**演示目标**：展示"写情绪日记 → 刷新兴趣标签 → Content-Based推荐方向变化"的链路

#### 操作步骤：

**Step 1：展示初始推荐状态**
```
1. 登录 student007
2. 进入"个性化推荐"页面
3. 观察推荐列表：
   - 主要围绕现有行为（时间管理、考试焦虑、情绪管理方向）
   - algorithm_type = user_cf + item_cf + content_based（无profile_based）
   - Content-Based返回结果少或为空（因为无兴趣标签）
```
> **讲解**："吴九有一些浏览行为但没有做测评。User-CF和Item-CF基于行为数据工作，但Content-Based因为缺少兴趣标签基本空转——因为没有测评自动写入标签，也没有手动刷新过标签。Profile-Based也因为没有心理画像而空转。"

**Step 2：写一篇情绪日记**
```
1. 进入"情绪日记" → 新建日记
2. 填写内容：
   - 日期：当天
   - 心情评分：3（偏低）
   - 情绪标签：勾选"焦虑"、"疲惫"
   - 日记内容：
     "最近数学专业课压力好大，期中考试快到了感觉复习不完。
      和室友关系也有点紧张，不知道该怎么沟通。"
3. 保存日记
```
> **讲解**："吴九写了一篇日记，内容是学业压力和人际困扰。系统会提取日记中的情绪标签（'焦虑'、'疲惫'）和关键词，这些信息会作为短期兴趣信号输入推荐系统。"

**Step 3：刷新兴趣标签**
```
1. 在"个性化推荐"页面点击"刷新"按钮
   （调用 POST /recommendation/refresh-tags）
2. 系统基于最近30天行为 + 日记情绪标签 → 重新计算兴趣标签
3. 查看新生成的标签（数据库验证）：
   - 预期新增：压力管理(behavior)、情绪调节(behavior)等
```
> **讲解**："刷新标签后，系统从吴九的浏览记录（时间管理、考试焦虑、情绪管理）和日记标签（焦虑、疲惫）中提取关键词，生成新的兴趣标签。这些标签会驱动 Content-Based 算法——现在标签向量不再是空的。"

**Step 4：查看推荐变化**
```
1. 返回"个性化推荐"页面
2. 观察推荐变化：
   - Content-Based 现在有结果了
   - 情绪管理相关资源可能排得更靠前
   - 考试焦虑/时间管理资源的 Content 匹配度提升
```

**覆盖场景**：情绪日记→兴趣标签刷新→Content-Based激活、行为数据驱动标签更新、无测评用户的推荐路径

## 七、答辩常见问题速答

**Q1：8个账号太多了，到底展示了什么？**
> 不是让老师看8遍推荐列表——6个静态账号展示不同心理问题方向（学业/抑郁/就业/适应/情感），2个操作账号展示动态变化（测评驱动 + 日记驱动）。核心是让老师理解"同样的推荐引擎，不同输入 → 不同输出"。

**Q2：推荐结果会不会每次都一样？**
> 首次请求后推荐结果缓存7天。演示前已执行 `DELETE FROM recommendation_result` 清空缓存，保证每次都是实时计算。如果演示过程中需要"复位"，重新执行 demo_prepare.sql 即可。

**Q3：student008从冷启动到有推荐，怎么证明不是随机的？**
> 冷启动时 algorithm_type = "hot"（兜底），做完测评后 algorithm_type = "profile_based" + "content_based"（不再是hot）。资源也从"全站热门"变成"抑郁相关"——如果随机不会每次都恰好推荐抑郁资源。

**Q4：为什么student002的推荐置信度比student004高？**
> student002有测评（中度抑郁）+ 画像 + 丰富行为，四路算法都有强信号。student004测评正常 → Profile-Based三个水平触发规则都不满足 → 只有三路有效。数据越丰富，推荐置信度越高——这是推荐系统的自然规律。

**Q5：心理画像推荐权重只有20%，为什么还说它很重要？**
> 看 student008 的演示——当其他三路算法全部空转时（新用户无行为），Profile-Based是唯一能给出有效推荐的算法。20%的权重在冷启动场景中实际是100%。它不是权重最高的，但它是永不断电的"安全气囊"。
